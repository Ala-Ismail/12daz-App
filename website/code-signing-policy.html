RELEASE TRANSPARENCY

Code signing policy

How official builds are authorized, and what the current signing status means for your download.

Current status

The published v0.1.5 executable is unsigned. The local Rust v0.2.0 candidate is also unsigned. We are exploring multiple options for trusted code signing. No signing provider has been selected, and signing is not yet active. We will update this page when a signing option is selected and activated.

Who authorizes a release?

The repository owner, Ala-Ismail, is the author/committer, reviewer and designated signing approver. External contributions require review. Code signing, once activated, will require manual release approval, multi-factor authentication and configured release protections.

The repository owner has confirmed that GitHub multi-factor authentication is enabled. Signing-service MFA and release protections remain pending confirmation before signing can be activated.

Cloning or forking the project does not give access to its signing identity. Only verified official release artifacts will be submitted; upstream libraries will not be signed as our own software.

Privacy and network behaviour

This program will not transfer any information to other networked systems unless specifically requested by the user or the person installing or operating it.

Conversion and reports stay on your computer. The current app has no telemetry, automatic update checks or survey uploads. The optional support link opens PayPal in your browser only when clicked.

Browser visits and downloads are governed by the relevant service's privacy policy: PayPal, GitHub and Vercel. Signing services receive build artifacts, not your survey files.

Check your download

Use official GitHub Releases and their SHA-256 checksums. Checksums verify download integrity; they do not replace a publisher signature. A signature does not certify CAD fidelity or guarantee that SmartScreen warnings disappear.

The full repository policy includes signature-checking instructions, release requirements and responsibilities. Non-sensitive questions can be raised in GitHub Issues; do not post private survey files.
